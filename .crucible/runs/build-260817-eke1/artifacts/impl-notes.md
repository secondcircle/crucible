# Slice 1 — `scaffold-dev-loop` — implementation notes

Realizes D2 (π SDK only in main, behind a sandboxed renderer), D5 (remote
debugging always on, fixed port 9222) and D10 (vitest + Testing Library +
jsdom). Nothing from slices 2–7 was implemented: no agent port types, no
adapters, no log sink, no preload surface, no import fence, no `dev:sdk` /

## How it was verified

Each of the slice's done-criteria, checked by running it:

1. **`npm run dev` opens the app, renderer sandboxed, bundled preload loading.**
   The app window opens on the vite dev URL. Runtime proof, not just source:
   the renderer child process runs with Chromium's `--enable-sandbox`, and
   `agent-browser eval` in the renderer reports
   `{"require":"undefined","process":"undefined","module":"undefined","crucible":"undefined","url":"http://localhost:5173/"}`.
   The preload emits `[info] [crucible] preload loaded` into the renderer
   console (seen via `agent-browser console`), from the single bundled file
   `out/preload/index.js` (0.06 kB).

2. **An edit hot-reloads.** With the app running, `Scaffold running.` →
   `Scaffold running — hmr probe.` in `src/renderer/src/App.tsx`;
   `agent-browser get text body` showed the new text within seconds and the
   console logged `[vite] hot updated: /src/App.tsx` with no second
   `[crucible] preload loaded` line — a hot update, not a reload. Edit reverted.

3. **`agent-browser connect 9222` then `snapshot`.** Works, and **A1 is
   settled in favour of electron-vite**: `electron-vite@5.0.0` has a
   `--remoteDebuggingPort` option that pushes `--remote-debugging-port=<port>`
   onto Electron's argv in dev, so `dev` is
   `electron-vite dev --remoteDebuggingPort=9222` and **main sets no switch**.
   A1's fallback (`app.commandLine.appendSwitch` under a dev guard) was not
   needed and was not written.

4. **Port facts recorded, port documented.** `lsof -nP -iTCP:9222 -sTCP:LISTEN`
   shows `Electron … TCP 127.0.0.1:9222 (LISTEN)` — loopback only, cross-checked
   with `curl` (loopback 200, LAN address refused), so no off-loopback finding.
   A launch against a busy 9222 still opens a window but logs
   `bind() failed: Address already in use (48)` /
   `Cannot start http server for devtools.`, does not fall back to another port,
   and leaves `agent-browser connect 9222` attached to the *first* app — proven
   by `location.href` reading `localhost:5173` while the second app served
   `5174`. All of it, verbatim, is in the evidence file; 9222 and the stale-app
   rule are now in `AGENTS.md`.

5. **`npm run lint`, `npm run typecheck`, `npm test` green.** Final run: lint
   clean, both tsc projects clean, vitest `1 passed (1)` in ~0.5 s.

No git state was touched: no commit, no branch, no staging.

## Two facts the document did not have (recorded, not deviations)

- **Preload filename.** Contracts writes the preload as
  `../preload/index.mjs`. This scaffold keeps `package.json` CommonJS, so
  electron-vite emits one CJS bundle at `out/preload/index.js` and
  `createMainWindow` points there; that file is verified to load under
  `sandbox: true` (check 1). The decision D2 realizes — one bundled file that
  loads under the sandbox — is unchanged; only the extension differs.
- **Electron 43 has no `postinstall`.** It ships an `install-electron` bin
  instead, so a bare `npm install` leaves `node_modules/electron/dist` missing
  and `electron-vite dev` fails with `Error: Electron uninstall`. The repo's
  `package.json` therefore runs `"postinstall": "install-electron"`, verified to
  fetch the binary. Also environmental: `jsdom@30.0.1` warns EBADENGINE on Node
  v25.9.0 (warning only — the jsdom test passes), TypeScript is pinned to ^5.9.3
  because typescript-eslint 8 caps at `<6.1.0` while the registry's latest is
  7.0.2, and `@vitejs/plugin-react` is pinned to ^5.2.0 because v6 requires
  vite ^8 while electron-vite 5 peers vite ^5–^7.
