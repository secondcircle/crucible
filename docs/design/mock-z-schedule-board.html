Behavior notes

The chip sits with the issue and branch chips, teal-marked because it is a run surface. Lit only while a run needs you; gone when the repo has no schedules. Feeds the Tab attention walk.

Needs you means parked: a question, a stall, or a failure. Clean completions never demand attention — they land in Recent with a report.

Take to a session adopts the run into a session (existing or new), where the ordinary orchestrator contract takes over. The board itself never answers a run.

Run now lives on the schedule rows' hover (not drawn): a schedule never blocks a manual run. On a checked schedule it skips the check — the user asked, so it fires.

Checks: a schedule may declare a predicate beside its cron — plain code the scheduler evaluates at fire time in a workflow host of its own. Falsy means nothing happened: no run, no worktree, no entry anywhere. A check that errors turns its last-word cell amber with the error; the chip stays unlit.
