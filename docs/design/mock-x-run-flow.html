◆ Mock X — the run graph: a real DAG, drawn, with room to read it

A workflow is not a line. It fans out into parallel reviewers, fans back in at a gate, sends work back for revision, and can carry independent subtrees that never touch each other. The run record already holds that shape — RunNode.parents is an arbitrary list and the engine runs nodes concurrently. What the run view draws is flex rows with one hairline down the middle, which is why three parallel reviewers look exactly like three strangers. Same layout as today, graph pane much bigger, edges actually drawn.

Layered top-down, edges drawn, one node per node. A fan-out is three lines leaving one card; a fan-in is three lines arriving at one. The pane is 640px and draggable; the transcript is a centred column either way, so the graph takes the gutter that was already dead. No text on the edges. A line says the work reached that node, and what reached it is the artifact rail's job — clicking a node fills the rail, and the node's own strip along the bottom reads took/made. Selecting a node lights its edges so its lineage stands out of a crowded graph. The teal marching line is work in flight right now; dashed grey is a path not yet walked.

2 · The edge vocabulary

ran after, and took its work
an edge of the selected node
being walked right now
planned, not yet walked
sent back for revision — the edge that goes up the page
A line means one thing: the work of the node above reached the node below. It never says which file carried it — the artifact rail owns dataflow, and duplicating it on the edges is how a seventeen-node graph turns into a wall of file names. Colour never carries meaning alone: a node's status is a word on its card, and the four edge states differ in shape as well as hue.
