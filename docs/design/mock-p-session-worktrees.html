Why the chip and not a toggle. Q5 asks for a control beside model and thinking, and those are chips. A switch would be the only switch in the row. The chip carries its own state as its label, which is what lets one element cover all six states above.

◇ checkout / ⑂ branch. Q11 struck any umbrella word, so the chip never says "venue" or "isolation" — it says where the session works, in the two terms CONTEXT.md now defines. Clicking the checkout chip creates a worktree; there is no third state and no menu, per Q12.

Locked is dimmer, not annotated. Q5: "merely non-interactable — no explanatory text, nothing over the top." State d drops opacity and the pointer, and says nothing. A session reset returns it to state a or c.

Failure borrows the transcript's code styling rather than inventing an error surface, and the chip is already back to checkout before the user reads it, so the two agree. No bootstrap-spec document, per Q14.
